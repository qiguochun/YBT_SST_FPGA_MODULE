# 10 — 实践路线与调试建议

前面九篇是“读懂”。这篇告诉你 **按什么顺序动手**，以及从 Verilog/Vivado 习惯迁过来时会踩的坑。

---

## 1. 第一周上手顺序

### Day 1：环境

1. 安装 Quartus 18.1 Standard + Cyclone V 器件包 + USB-Blaster 驱动。  
2. 打开 `SSTMC_FPGA.qpf`，Start Compilation，确认能出 `output_files/SSTMC_FPGA.sof`。  
3. 对照 `03` 把引脚表打印一张，和原理图对 10 个关键脚：CLKIN、zz/zc、FHS、UAD、LED。

### Day 2：VHDL 阅读

1. 只读 `04` 对照表，把 `SSTMC_FPGA.vhd` 头 200 行（PORT + SIGNAL + 调试赋值）用笔标一遍。  
2. 在 Quartus 里 RTL Viewer 看顶层例化：PLL、两个 TX_Comm、两个 AMC。

### Day 3：通信

1. 精读 `TX_Comm` 状态 0～22，在纸上画出帧头波形。  
2. 对照 `08` 把 zz 下行 54 bit 画成格子，假设一帧全 0 / 一帧命令 `11010_11010` 看解码会怎样。

### Day 4：PWM

1. 用计算器验算 80 kHz、1.6 µs 死区。  
2. 分清：哪些脚当前是调试波，哪些是真正 HB 输出。

### Day 5：改一处无风险逻辑验证工具链

例如：只改 `F_LED` 极性或闪烁分频，编译下载，确认 LED 行为变了。不要第一步就改 PWM 死区。

## 2. 推荐的 SignalTap / 仿真观察点

Quartus 在线逻辑分析：Tools → Signal Tap Logic Analyzer（类似 Vivado ILA）。

| 场景 | 建议抓的信号 | 时钟 |
|------|----------------|------|
| 光纤是否通 | `zz_r`, `sig_zzFiberT`, `sig_zzFinish`, `sig_zzsinFt`, `sig_Cerr(6)` | 50 M |
| 命令是否锁存 | `sig_CLR`, `sig_HPwm`, `sig_Dauto`, `sig_HPwma` | 50 M |
| HB 死区 | `sig_HPwma`, `sig_HPwmDa`, `FHS1_DRV`, `FHS2_DRV` | 120 M |
| 软启进度 | `sig_Dsoft`, `sig_Dpwm`, `sig_Fauto`, `Driveou1` | 50 M |
| 均流 | `sig_I1O`, `sig_Idzl`, `CH1_fI`, `new_max_a` | 50 M |
| 电压 | `sig_UhO`, `sig_UdGY`, `sig_Cerr(10)` | 50 M |

仿真：`simulation/modelsim/SSTMC_FPGA.vht` 若为空壳，可先写一个只翻转 `CLKIN`、把 `zz_r` 接回 `zz_t` 的环回 TB，看 `TXFinish` 是否周期性出现（注意发送取反，环回可能要再反一次）。

## 3. 改代码检查单

- [ ] 新增 `SIGNAL` 是否被两个 PROCESS 驱动（非法）  
- [ ] 整数 `RANGE` 是否会被运算溢出（仿真能跑、综合截断）  
- [ ] 120 MHz 进程里不要新增大除法/大 CASE  
- [ ] 改 `TX_Comm` GENERIC 必须对端 FPGA 同步改  
- [ ] 改 PLL 频率必须重算所有 `Num*`、`BS_MAXCNT`、分频常数  
- [ ] 恢复 `PWM_DCbs` 前先拿掉 `FL* <= CLKIN` 那 6 行，否则多驱动  
- [ ] 保持 `STD_LOGIC_arith` 风格，不要突然改成全 `unsigned()` 混运算

## 4. Verilog 习惯在本工程里的坑

| 习惯 | 后果 |
|------|------|
| 把 `&` 当按位与 | VHDL 里变成拼接，综合结果完全错 |
| 用 `==` | 语法错，要用 `=` |
| 敏感表漏时钟却写了异步复位条件 | 出锁存或仿真综合不一致 |
| 认为 `VARIABLE` 和 `reg` 一样跨进程可见 | 编译都过不了 |
| 同一 bit 在 LED 进程和保护进程都写 | 多驱动 |
| 拿 Rock 的 XDC 思维找 `.sdc` | 本工程约束几乎全在 `.qsf` 引脚，时序靠工具默认 |
| 用 Vivado 的 `(* mark_debug *)` | Quartus 要用 SignalTap 节点或 `keep` 属性 |

---

## 5. 源码里已确认的“坑 / 未完成”

读代码时这些不是你理解错，是当前版本真实状态：

1. **低压 PWM 脚被调试占用**，正式 `PWM_DCbs` 整段注释。恢复功率输出必须删掉顶层 6 行 `FL*<=` 再解开进程，否则多驱动。  
2. **`F_FLT1~4` 滤波在跑，置故障被注释**，驱动硬件故障不进总闭锁。  
3. **风扇反馈、风扇故障位未启用。**  
4. **`FHOE_DRV` / `FLOE_DRV` 恒 `'0'`。**  
5. **AMC1305 的 `clk_div_cnt` 运行中不再赋值**，解调条件实际只剩 `sclk=0`（AMC1035 则有 `clk_div_cnt<=cnt`）。改采样沿时注意两边不对称。  
6. **`BS_MDUCNT` 定义未使用。**  
7. 库 `STD_LOGIC_arith` + `NUMERIC_STD` 混用，新代码容易运算符歧义。

---

## 6. 功能尚未闭合、接手时优先问硬件的问题

1. `FL1S1`～`FL3S2` 现网到底接驱动还是测试点？  
2. `FHOE_DRV`/`FLOE_DRV` 有效电平？  
3. 从控 FPGA 是否同一套 `TX_Comm` 头尾？位宽 43/21 是否匹配？  
4. AMC1305 SCLK 20 MHz、AMC1035 5 MHz 是否在芯片允许范围？  
5. 风扇 PWM 极性、额定给定 `P23t` 标幺？  
6. 系统主控那端组帧文档（若有纸质协议）是否与第 8 篇一致——**以本仓库代码为准还是以上位机为准**，两边必须先对齐。

---

## 7. 若要把某段迁到 Rock（或反过来）

| 可迁 | 不可直接迁 |
|------|------------|
| PI 均流差分方程 | TX_Comm（物理层不同） |
| 三角波 PWM + 死区思路 | AMC ΔΣ 驱动（Rock 是 XADC） |
| 故障锁存 + 回差 | 引脚与器件原语 |
| 命令 5 帧滤波 | Quartus IP |

语言本身：算法用 INTEGER 写的，改 Verilog 就是 `integer` + `always @(posedge clk)`。难点在标定系数和位权，不在 VHDL 语法。
