# 01 — Rock vs YBT：两工程对比总览

先建立一张“旧工程 → 新工程”地图，避免用 Rock 的整机架构去套 YBT。

---

## 1. 产品定位

| 维度 | RockDcCtrlTop（旧） | YBT / SSTMC_FPGA（当前） |
|------|---------------------|--------------------------|
| 角色 | 整机 DC 变换器主控 | SSTMC **功率单元主控** |
| 上下级 | 以太网对接 ARM/上位机；内部嵌 Cortex-M0 | **光纤**：系统主控 ↔ 本单元主控 ↔ 单元从控 |
| 功率拓扑 | Buck-Boost + 双 LLC（高低压侧） | **H 桥（HB）** + **直流侧 DC（Boost 软启 + 变频工作）** |
| 控制复杂度 | 多核（FPGA 逻辑 + Cortex-M0 + DDR 录波） | 单片 FPGA，控制逻辑几乎全在顶层 `SSTMC_FPGA.vhd` |
| 源码规模 | 上百个 `.v` 模块 | 有效用户代码约 **4 个 VHDL 文件** + IP |

YBT 名称线索：

- 目录：`YBT_FPGA_SSTMC20260817_fan`
- 顶层实体：`SSTMC_FPGA`
- 后缀 `_fan`：本版本含风扇 PWM（`FFAN_*`）

**SSTMC** 可按“固态变压器 / 级联模块化变换器的功率单元”理解：多单元级联，每个单元有一块 FPGA 做本地采样、PWM、保护，并通过光纤与系统主控、单元从控交换数据。

---

## 2. 硬件与工具链

```
Rock:   Verilog  → Vivado          → Xilinx Artix-7  xc7a50tfgg484-2
YBT:    VHDL     → Quartus Prime 18.1 → Intel Cyclone V  5CEBA2F17C8
```

| 项目 | Rock | YBT |
|------|------|-----|
| 工程文件 | `.xpr` | `.qpf` + `.qsf` |
| 约束 | `.xdc`（引脚+时序） | 引脚写在 `.qsf`；本工程几乎无独立 `.sdc` |
| IP | Clock Wizard / MIG / XADC / FIFO | `sz_pll`（50M→120M）、`RAM_16_2048` |
| 配置器件 | 视板卡 | `EPCQ16A`，AS x4，100 MHz |
| 仿真 | 自建大量 `Sim/*Tb` | 指向 `simulation/modelsim/SSTMC_FPGA.vht` |

详细工具操作见 `02_Quartus开发环境上手.md`，芯片见 `03_芯片与引脚说明.md`。

## 3. 目录结构对照

### Rock（模块化、分层）

```
RockDcCtrlTop/
  Dev/RockDcCtrlTop/     Vivado 工程
  Src/UserCode/          业务 Verilog（几十个 Core）
  Src/Core/              Xilinx IP
  Src/Ucf/               XDC
  Sim/                   各模块 Testbench
  Doc/                   原理图、DDR、Matlab
```

### YBT（扁平、几乎全在顶层）

```
YBT_FPGA_SSTMC20260817_fan/
  SSTMC_FPGA.qpf / .qsf      工程与约束
  SSTMC_FPGA.vhd             ★ 顶层：通信解码、PWM、保护、风扇（1306 行）
  TX_Comm.vhd                光纤比特帧收发
  AMC1305_16bit_Controller.vhd   直流电压 ΔΣ 采样
  AMC1035_5CH_Controller.vhd     5 路温度 ΔΣ 采样
  RAM_16_2048.vhd            电压滑动平均用 RAM（MegaWizard）
  sz_pll.vhd                 PLL IP 封装
  output_files/              综合/适配输出（sof/pof/rpt）
  simulation/                ModelSim 相关
```

对 Verilog 工程师的含义：YBT **没有** Rock 那种 `ProtectCore / PwmTransferCore / EthCmdAnalysisCore` 分层。读代码时要从顶层 `ARCHITECTURE` 里按注释分区走读（第 0～9 段），而不是按文件名找模块。

## 4. 功能模块映射（经验迁移）

Rock 里你会的能力，在 YBT 中对应如下：

| Rock 模块/能力 | YBT 对应 | 差异要点 |
|----------------|----------|----------|
| `SysPllCore` 多时钟 | `sz_pll`：50 MHz → 120 MHz | YBT 只有 50M 晶振 + 120M PWM 时钟 |
| `SysRst` | 上电计数 `P_reset`（约 1 ms） | 无外部复位脚，纯内部软复位 |
| `PwmGenLLC` / `PwmGenBuckBoost` | `PWM_HBbs` + `BS_PWM` + `PHASE_PROC` | HB 开关由光纤直接下发；DC 有软启+变频 |
| `SlowLaunchCtrlCore` | `BS_DC` 软启状态机 | 占空比爬升 → 切入工作 PWM → 频率爬升 |
| `ProtectCore` | `sig_Cerr` / `sig_Dvft` + `P_GZSC` | 故障是位图，经光纤上报系统 |
| `UartCore` / 以太网协议 | `TX_Comm` 光纤自定义帧 | 不是 UART/ETH，是同步比特流+固定头尾 |
| XADC / 外部 ADC | AMC1305（电压）+ AMC1035（温度） | ΔΣ 比特流，FPGA 做 OSR 计数 |
| `Fan` PWM | `TrFAN` | 占空比由系统参数 `sig_P23t` 下发 |
| Cortex-M0 + DDR 录波 | **无** | 不做录波、不做以太网、不跑 CPU |
| 继电器 | **无** | 单元级功率开关由驱动芯片完成 |

## 5. YBT 当前源码里必须知道的“现状”

读代码时不要被端口名误导，以下几处是**当前版本的实际接线**，和注释里的“正式驱动”不完全一致：

1. **低压侧 DC PWM 正式输出进程被注释掉了**  
   `PWM_DCbs` 整段在注释中。真正驱动 `FL1S1_DRV`～`FL3S2_DRV` 的是顶层开头的调试映射：

   - `FL1S1_DRV <= CLKIN`
   - `FL1S2_DRV <= sig_clk20KHz`
   - `FL2S1/FL2S2 <= HB PWM 原始波形`
   - `FL3S1 <= sig_RES`，`FL3S2 <= sig_clkMHz`

   这意味着：**当前 bitstream 很可能把低压 PWM 脚当调试观察口**，DC 功率开关并没有按注释逻辑输出。改功能前先确认硬件是否仍按此连接。

2. **器件故障 `F_FLT1~4` 的置位被注释**  
   `Dv_Ft` 里检测到低电平超时后，`sig_Dvft(0~3) <= '1'` 被注释，硬件故障暂不上报到总故障。

3. **风扇反馈 `FFAN_FB1` 未参与保护**  
   `TrFAN` 里对风扇反馈的判断被注释；`sig_Cerr(12)` 风扇故障也未启用。

4. **HB 输出使能 `FHOE_DRV`、DC 输出使能 `FLOE_DRV` 恒为 `'0'`**  
   若驱动芯片是高有效使能，当前等于一直关闭使能脚（可能板级另有接法，需对照原理图）。

以上不影响你理解算法，但**改板/改功能时必须先核对原理图**。

## 6. 时钟与实时性对比

| | Rock | YBT |
|--|------|-----|
| 输入时钟 | 板级晶振（经 PLL 出 50/100/200 MHz 等） | `CLKIN` = **50 MHz** |
| PWM 时钟 | 多时钟域 | `sig_clkMHz` = **120 MHz**（PLL） |
| 通信节拍 | 以太网包 | `sig_clk20KHz`：**20 kHz** 触发一帧光纤收发 |
| 指示灯慢钟 | LED 分频 | `sig_clk5Hz`：5 Hz |

关键公式（YBT）：

- HB 死区：`NumHSQ=192` / 120 MHz ≈ **1.6 µs**
- DC 死区：`NumDSQ=24` / 120 MHz = **200 ns**
- Boost 载波：`BS_MAXCNT=750` → 三角波往返 1500 拍 / 120 MHz = **80 kHz**

## 7. 读代码的正确姿势

对 Rock 你习惯：打开 `RockDcCtrlTop.v` → 看例化树 → 下钻某个 Core。

对 YBT 建议：

1. 打开 `SSTMC_FPGA.vhd` 的 **PORT** 和文件头 **CONSTANT**。
2. 按注释数字分区跳转：`0.LED` → `1.复位+时钟` → `2.zz通信` → `3.zc通信` → `4.均流` → `5.Boost PWM` → `6.Work PWM` → `7.死区` → `8.采样保护` → `9.器件故障`。
3. 子文件只在需要时打开：光纤细节看 `TX_Comm.vhd`，电压看 `AMC1305_*.vhd`，温度看 `AMC1035_*.vhd`。
