## 1. 先建立整体图景

把 FPGA 想成一座“可编程工厂”，五类资源分别是：

| 资源 | 像什么 | 主要干什么 |
|------|--------|------------|
| **LE / ALM** | 通用加工台 | 做组合逻辑、状态机、计数器、比较器……几乎一切“逻辑” |
| **片内 RAM** | 仓库货架 | 存数据、缓存、查找表、FIFO、系数表 |
| **DSP 块** | 专用算术流水线 | 快速做乘法、乘加、滤波、相关等数学运算 |
| **PLL** | 时钟工厂 | 把外部晶振变成多个稳定内部时钟 |
| **用户 I/O** | 工厂大门 | 和板子上的 ADC、通信口、指示灯、CPU 等对接 |

重要原则：

- **它们不是无限的**，用超了编译会失败或布线极困难  
- **它们可以互相“顶替”但不划算**（例如用逻辑硬拼乘法，会很吃 LE）  
- Quartus 编译后会告诉你每类资源用了百分之多少

对 **5CEBA2（A2 档）**，官方最大资源量级如下：

| 项目 | 大约数值 |
|------|----------|
| Logic Elements (LE) | **25,000** |
| ALM | **约 9,430** |
| 寄存器（Register） | **约 37,736** |
| M10K 存储器 | **1,760 Kb**（176 个 × 10 Kb） |
| MLAB 存储器 | **196 Kb** |
| 片内 RAM 合计 | **约 1,956 Kb ≈ 1.91 Mb**（常口头说“约 2 Mb”） |
| 可变精度 DSP 块 | **25** |
| 等效 18×18 乘法器 | **50** |
| PLL | **4** |
| 器件理论最大 GPIO | 最高可到约 **224**（更大封装） |
| **F17 封装用户 I/O** | **约 128** |

## 2. 逻辑资源：约 25,000 LE / 约 9,430 ALM

### 2.1 什么是 LE？

**LE = Logic Element（逻辑单元）**

这是 Intel/Altera 传统宣传口径里的“逻辑规模单位”，便于不同型号横向比较。

你可以粗浅理解：

> 1 个 LE ≈ 能实现一小块组合逻辑 + 可能带 1 个触发器的“最小积木”。

所以说「25,000 LE」大致表示：

- 这块芯片大概能放下“两万五千份基础逻辑积木”量级的设计  
- 不是说你只能写 25000 行代码  
- 也不是说你有 25000 个独立功能模块

### 2.2 什么是 ALM？

**ALM = Adaptive Logic Module（自适应逻辑模块）**

这才是 Cyclone V **硅片上真实的基本逻辑块**。

在 Cyclone V 中，一个 ALM 能力很强，通常可以：

- 实现较复杂的查找表（LUT）组合逻辑  
- 内含可配置的加法器进位链结构  
- 提供多个寄存器（触发器）  
- 在某些模式下参与分布式存储（变成 MLAB 的一部分）

官方给出 A2 档：

- **ALM ≈ 9,430**
- **LE ≈ 25,000**

二者关系可记：

\[
1\ \text{ALM} \approx 2\sim3\ \text{LE 的等效宣传能力}
\]

（因为一个 ALM 比老架构单个 LE 更“胖”、功能更强。）

### 2.3 LE 和 ALM 为什么两个都报？

| 口径 | 用途 |
|------|------|
| **LE** | 营销/选型时比较“逻辑规模” |
| **ALM** | Quartus 报告、真实布局时更贴近硅片结构 |

你在 Quartus 的 Project Navigator / Compilation Report 里，更常看到：

- `Logic utilization (ALMs)`  
- `Combinational ALUT`  
- `Dedicated logic registers`

也就是说：**做工程时盯 ALM/寄存器占用更实用；看产品页时看 LE 更常见。**

### 2.4 逻辑资源具体都能实现什么？

几乎所有“数字控制逻辑”都吃 LE/ALM，例如：

- `if/else`、`case` 状态机  
- 计数器、分频器（也可用 PLL，但简单分频常吃逻辑）  
- 比较器、编码器、译码器  
- 串并转换、协议解析（SPI/UART 软核）  
- 有限状态控制 ADC、通信时序  
- 用逻辑硬实现的小型乘法/加法（不推荐大位宽）

### 2.5 “用了多少逻辑”怎么理解？

假设编译报告写：

> Logic utilization: 35%

含义接近：

- 约 35% 的 ALM 已被占用  
- 还剩约 65% 余量可继续加功能  

经验参考（非绝对标准）：

| 占用 | 体感 |
|------|------|
| < 40% | 很轻松，布线通常友好 |
| 40%–70% | 正常工程范围 |
| 70%–85% | 开始紧张，时序更容易出问题 |
| > 85%–90% | 高风险区，小改动都可能编不过或时序炸 |

### 2.6 寄存器（Register）为什么单独提？

A2 档大约有 **37,736** 个寄存器资源潜力。

寄存器就是“能记住 0/1 的小盒子”，对应 VHDL 里时钟沿触发的信号，例如：

```vhdl
process(clk)
begin
  if rising_edge(clk) then
    q <= d;
  end if;
end process;
```

注意：

- 寄存器数量和 ALM 有关，但不是简单一一对应  
- 设计里大量流水线、移位寄存器会明显推高寄存器占用  
- 有些存储若用寄存器堆实现，会非常吃寄存器；大数组应优先用 RAM

### 2.7 小例子：同样功能，消耗差很多

| 写法/结构 | 资源倾向 |
|-----------|----------|
| 纯组合大 `case` | 吃组合逻辑（ALUT） |
| 多级流水寄存器 | 吃寄存器，但时序更好 |
| 大查找表用逻辑拼 | 很吃 ALM |
| 大查找表放 RAM | 省 ALM，改吃 RAM |

## 3. 片内 RAM：约 2 Mb 量级

### 3.1 “约 2 Mb”到底是多少？

官方汇总（Cyclone V E · A2）：

| 类型 | 容量 |
|------|------|
| **M10K** | **1,760 Kb** |
| **MLAB** | **196 Kb** |
| **合计** | **1,956 Kb ≈ 1.91 Mb** |

换算：

- \(1\ \text{Mb} = 1024\ \text{Kb}\)（这里按二进制惯用）  
- \(1956\ \text{Kb} \div 1024 \approx 1.91\ \text{Mb}\)  
- 若按位数：约 \(1956 \times 1024 \approx 2,002,944\ \text{bits}\)，所以很多器件页写成 **2,002,944 Total RAM Bits**

口头说“约 2 Mb”是合理的。

### 3.2 两类片内存储器：M10K 与 MLAB

#### （1）M10K —— 专用块 RAM（主力仓库）

- 每个块标称 **10 Kb**  
- A2 档约有 **176 个** M10K  
- \(176 \times 10\ \text{Kb} = 1,760\ \text{Kb}\)

适合：

- 较大容量 RAM / ROM  
- FIFO  
- 双端口缓存  
- 系数表、波形表  
- 跨时钟域的存储型缓冲（配合正确设计）

特点：

- 是“硬核存储器”，不占用（或极少占用）通用逻辑去“拼存储”  
- 有最小深度/宽度配置规则，由 Quartus 自动映射  
- 支持 ECC 等能力（视用法与器件特性）

#### （2）MLAB —— 分布式浅存储（小而快/宽）

- 由部分 ALM 配置而来  
- A2 档合计约 **196 Kb**  
- 单个 MLAB 量级约 **640 bit** 级分布式结构  
- 适合“又宽又浅”的小存储

适合：

- 小型浅 FIFO  
- 短延迟线  
- DSP 里的抽头延迟  
- 很小的查找表/移位结构

注意：

- MLAB 用多了，等于占用本可用于普通逻辑的 ALM  
- 所以它是“逻辑与小存储之间的柔性资源”

### 3.3 位宽 × 深度 = 你真正需要的容量

存储器需求公式：

\[
\text{总位数} = \text{位宽} \times \text{深度}
\]

例子：

| 需求 | 计算 | 约占 |
|------|------|------|
| 16-bit × 2048 深 | \(16 \times 2048 = 32768\ \text{bit} = 32\ \text{Kb}\) | 很小一块 |
| 32-bit × 4096 | \(128\ \text{Kb}\) | 仍轻松 |
| 很多通道各开大 FIFO | 很快叠到数百 Kb | 开始要精打细算 |

你工程里有 `RAM_16_2048` 这类命名，很典型就是：

> 16 位宽、深度 2048 的片内 RAM（约 32 Kb）

这对 2 Mb 总量来说非常小，说明单看这个模块，存储器压力不大；真正要盯的是“一共实例化了多少个、够不够、会不会碎片化浪费”。

### 3.4 “有 2 Mb”不等于“随便开 2 Mb 都能完美放下”

原因：

1. **块是离散的**：要用整数个 M10K，可能产生浪费  
2. **端口模式限制**：单口/简单双口/真双口配置不同，消耗不同  
3. **位宽对齐**：某些宽而浅、或奇异位宽，映射效率差  
4. **同时还有路由与时钟域约束**

所以手册最大值是上限，不是“你声明多大就保证完美塞下多大”。

### 3.5 RAM 和寄存器堆的区别（新手极易混）

| 对比 | 片内 RAM（M10K/MLAB） | 寄存器堆（一堆 flip-flop） |
|------|------------------------|----------------------------|
| 容量效率 | 高 | 很低 |
| 适合大数据 | 是 | 否 |
| 异步复位/任意初始化 | 有限制，需按模板写 | 更灵活但昂贵 |
| 同一时刻可读地址数 | 受端口数限制 | 可很灵活但极耗资源 |
| 典型用途 | 缓存、FIFO、表 | 流水线、状态、少量暂存 |

**经验法则：深度超过几十/上百，优先考虑 RAM，不要用数组寄存器硬扛。**

## 4. DSP：约 25 个可变精度块（约 50 个 18×18 乘法）

### 4.1 什么是 DSP 块？

**DSP = Digital Signal Processing Block（数字信号处理硬核）**

它是芯片里做好的“乘法/乘加专用电路”，比用普通逻辑拼乘法：

- 更快  
- 更省逻辑  
- 功耗和时序通常更好

A2 档：

- **可变精度 DSP 块：25 个**  
- **等效 18×18 乘法器：50 个**

为什么 25 块能对应 50 个 18×18？  
因为 **1 个可变精度 DSP 块内部可配置成多个较小乘法器**。例如常见能力包括：

- 多个 9×9  
- 两个 18×18  
- 一个更大位宽乘法（如接近 27×27 量级，视具体模式）

所以宣传时常用“18×18 乘法器个数”衡量算力。

### 4.2 “可变精度”是什么意思？

同一个 DSP 硬核，可按算法需要切成不同位宽模式，而不是只能做一种固定乘法。

典型可支撑的运算形态：

- 乘法：`A * B`  
- 乘加：`A * B + C`（MAC，滤波核心）  
- 预加后再乘：`(A±B)*C`（对称滤波很常用）  
- 累加器、级联（做更长滤波器、矩阵运算片段）

### 4.3 什么时候会用到 DSP？

| 应用 | 是否吃 DSP |
|------|------------|
| FIR / IIR 滤波 | 是，强烈 |
| 相关、卷积 | 是 |
| 数字下变频、混频 | 是 |
| PID 等控制里的乘运算 | 可能 |
| 图像缩放/简单矩阵 | 可能 |
| 纯状态机、协议解析 | 基本不吃 |
| 加减、移位 | 通常不需要 DSP |

若代码里写了宽位乘法：

```vhdl
y <= a * b;  -- a、b 较宽时
```

Quartus 往往会自动推断并映射到 DSP 块（也可能因写法/属性而用逻辑实现）。

### 4.4 25 个 DSP 算多算少？

对 **控制 + 采集 + 通信** 类工程：通常足够。  
对 **大量并行滤波/高阶多通道 DSP**：可能紧张。

粗略直觉：

- 1 个实数 FIR，若每拍算很多抽头，可能连续吃多个 DSP  
- 多通道同时并行，消耗近似线性上涨  
- 时间复用（一个乘法器分时算多个通道）可省 DSP，但要更复杂控制

### 4.5 DSP 和 LE 的替代表

| 实现方式 | 优点 | 缺点 |
|----------|------|------|
| 用 DSP 硬核 | 快、省逻辑、时序好 | 数量有限 |
| 用 LE 拼乘法 | 灵活 | 很吃逻辑、慢、难收敛时序 |

**结论：能进 DSP 的乘法，尽量让它进 DSP。**

## 5. PLL：最多约 4 个

### 5.1 什么是 PLL？

**PLL = Phase-Locked Loop（锁相环）**

作用一句话：

> 输入一个参考时钟（例如板载 50 MHz 晶振），在片内生成一个或多个频率/相位满足要求的时钟。

常见能力：

- 倍频：50 MHz → 100 / 150 / 200 MHz  
- 分频：50 MHz → 25 / 10 MHz  
- 多路输出：同时给出系统时钟、采样时钟、通信时钟  
- 相位调整、占空比相关配置（视 PLL IP 模式）  
- 提供 `locked` 信号：表示时钟已稳定锁定

### 5.2 为什么说“最多约 4 个”？

A2 档器件内嵌 **最多 4 个 PLL 硬核**。

注意“最多”的含义：

- 硅片上最多 4 个  
- 实际能用几个，还受封装、是否引出时钟输入脚、你怎么配置影响  
- 每个 PLL 可输出多路时钟，所以 **4 个 PLL ≠ 只能有 4 个时钟**

### 5.3 和“逻辑分频”有何区别？

| 方式 | 做法 | 优点 | 风险 |
|------|------|------|------|
| **PLL** | 硬核生成时钟 | 质量高、可上全局时钟网络 | 数量有限，配置要正确 |
| **计数器分频** | 用逻辑对时钟计数打拍 | 简单 | 易产生劣质时钟、时序难、不推荐做主系统时钟 |

新手原则：

> **系统主时钟、采样时钟，优先走 PLL；不要随手用逻辑门/计数器“造时钟”去驱动大量寄存器。**

### 5.4 和你工程的直接关系

工程中有 `sz_pll`（Quartus PLL IP 生成）。典型用法是：

- 输入：`refclk`（外部参考钟）  
- 输出：`outclk_0`（片内工作钟）  
- 可选：`locked`（锁定指示）

这说明本设计已经在用 PLL 资源。  
A2 一共 4 个，若以后再加多个独立时钟域 PLL，需要盘点是否超限，或合并到同一 PLL 的多输出。

### 5.5 PLL 用满了会怎样？

- IP/编译阶段报 PLL 资源不足  
- 或被迫改用逻辑分频（性能/可靠性下降）  
- 或改架构：减少独立时钟、改用同源多输出

## 6. 用户 I/O：本封装约 128

### 6.1 先分清三个容易混的数字

对 `5CEBA2F17C8`：

| 数字 | 含义 |
|------|------|
| **256** | 封装焊球总数（F17 = 17×17 mm FBGA，256 balls） |
| **约 128** | 可作为用户 I/O 的引脚大约数量 |
| **其余球** | 电源、地、配置、专用功能等，不能当普通 IO 乱用来接业务信号 |

所以：

> **不是 256 个球都能接你的 ADC/UART。真正给你用的大约 128 个用户 I/O。**

### 6.2 什么是用户 I/O？

**User I/O / GPIO**：可在 Pin Planner 里分配给设计端口的通用输入输出脚。

用途包括：

- 输入：时钟、复位、ADC 数据、传感器、UART RX……  
- 输出：DAC/控制线、UART TX、指示灯、片选、时钟输出……  
- 双向：数据线、总线接口……

### 6.3 为什么器件页写最大 GPIO 能到 224，你却只有约 128？

因为：

- **224** 是该硅片在更大封装下的理论最大 GPIO 量级  
- 你用的是 **F17（256 球）小封装**，引出的用户 IO 更少  
- **封装决定了你能用到多少脚**，不是只看硅片型号前缀

选型时永远要看：

1. 器件密度（A2/A4…）  
2. **具体封装（F17/F23…）**  
3. 温度与速度等级（C8 等）

### 6.4 128 个 IO 看起来很多，为什么实际很快不够？

因为一个“功能”往往要很多脚：

| 功能举例 | 可能占用 |
|----------|----------|
| UART | 2 根（TX/RX）看起来很少 |
| SPI | 4+（SCLK/MOSI/MISO/CS…） |
| 并行 ADC 数据 | 位宽条数直接线性增加 |
| 多通道同步采集 | 数据 + 时钟 + 帧信号 |
| 调试灯/测试点 | 也占 IO |
| 差分对 | 一对占 2 个球，且位置有约束 |

此外还有限制：

- 不是任意 IO 都能当优质时钟输入  
- 不同 Bank 电压标准（3.3V/2.5V/1.8V 等）要匹配外围芯片  
- 高速/差分还有专用走线与 bank 规则

### 6.5 和管脚分配的关系

在 Quartus 中：

- `Assignments → Pin Planner`：把 VHDL 端口绑到具体引脚号（如 `PIN_A12`）  
- 管脚分配错误时：  
  - 可能编译过，但板子功能错  
  - 或违反电压/专用脚规则直接报错

**资源“有 128 个 IO”只说明物理上限；正确接到原理图对应网络，才是工程可用性。**

## 7. 五类资源怎么互相配合

一个典型采集通信系统，资源分工常常是：

```text
外部 50MHz 晶振
        │
        ▼
      PLL ──────────────────► 系统时钟 / 采样时钟
        │
        ▼
   逻辑 (ALM) ──────────────► 状态机、协议、控制时序
        │
        ├──── DSP ──────────► 滤波/乘加/标定运算（若有）
        │
        ├──── RAM ──────────► 采样缓存、FIFO、查找表
        │
        ▼
   用户 I/O ◄──────────────► ADC / 通信口 / 指示灯 / 上位接口
```

记住这条资源经济原则：

1. **时钟走 PLL**  
2. **大存储走 RAM**  
3. **重乘法走 DSP**  
4. **控制与胶水逻辑走 ALM**  
5. **对外连接精算 I/O**

反模式（新手常踩）：

- 用逻辑分频当主时钟  
- 用巨量寄存器数组当大 FIFO  
- 大位宽乘法却迫使综合成 LE  
- IO 随便分配，忽略电平与时钟脚

## 9. 编译报告里这些数字在哪看

路径（Quartus）：

1. 编译完成后打开 **Compilation Report**

| 报告项 | 你要找的内容 |

- `PLLs`  
- `I/O pins`

## 10. 小白常见误解

### 误解 1：25,000 LE = 能写 25,000 个模块  
否。这是逻辑容量量级，不是模块个数。

### 误解 2：有 2 Mb RAM，我就能存 2 Mb 的“文件”  
不完全。这是片内比特容量上限，且受块结构、端口、映射效率限制；也不是外挂 DDR 那种大内存。

### 误解 3：25 个 DSP 很少，是不是芯片很弱？  
对控制类足够；只有高并行信号处理才会显得紧。关键看算法要不要大量乘法。

### 误解 4：4 个 PLL = 只能有 4 个时钟  
否。一个 PLL 可多路输出；也可以多个时钟同源。真正受限的是 PLL 硬核个数与时钟网络规划。

### 误解 5：256 脚封装就有 256 个用户 IO  
否。`F17` 约 **128** 用户 IO，其余多为电源地和专用脚。

### 误解 6：资源没用满就一定时序没问题  
否。即使只用 20% 逻辑，时钟太快、路径太长、约束不对，照样 Timing Violation。

### 误解 7：BGA 的 128 个 IO 都能随便当输入时钟  
否。专用时钟输入脚、全局时钟网络质量更好；普通 IO 当时钟有限制。

## 结束语

这五类数字不是抽象参数，而是你做 FPGA 时的“预算表”：

- **逻辑**决定控制复杂度上限  
- **RAM**决定能缓存多少数据  
- **DSP**决定数学运算并行度  
- **PLL**决定时钟体系能建多复杂  
- **I/O**决定能接多少外部世界  

先把这份预算读懂，再看编译占用，你就会从“只会点编译”迈向“知道自己在消耗什么”。
