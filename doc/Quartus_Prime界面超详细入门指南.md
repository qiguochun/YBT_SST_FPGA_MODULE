## 1. 先搞懂：这个软件是干什么的

**Quartus Prime** 是 Intel（原 Altera）出品的 FPGA 开发软件。

你可以把它理解成：

| 类比 | 软件开发 | FPGA 开发（Quartus） |
|------|----------|----------------------|
| 写代码 | VS Code / Visual Studio | 写 Verilog / VHDL |
| 编译 | 编译器生成 exe | 综合 + 布局布线，生成可烧录文件 |
| 运行 | 在电脑上运行程序 | 把文件下载到 FPGA 芯片里“变成硬件” |

你当前界面已经打开了一个工程：

- 工程名：`SSTMC_FPGA`
- 目标芯片：`Cyclone V` 系列，具体型号 `5CEBA2F17C8`
- 软件版本：`Quartus Prime Version 18.1.0 Build 625 Standard Edition`

一句话：  
**你在这里写硬件逻辑 → 编译成芯片配置文件 → 下载到板子上让硬件按你的设计工作。**

## 3. 标题栏

顶部标题类似：

`SSTMC_FPGA - Quartus Prime - D:/CODE/.../SSTMC_FPGA.qpf - Cyclone V`

含义拆解：

| 内容 | 意思 |
|------|------|
| `SSTMC_FPGA` | 当前工程名称 |
| `Quartus Prime` | 软件名称 |
| `...SSTMC_FPGA.qpf` | 工程文件完整路径（`.qpf` = Quartus Project File） |
| `Cyclone V` | 当前工程目标器件系列 |

小白注意：

- `.qpf`：工程主文件，双击它就能用 Quartus 打开工程
- `.qsf`：工程设置文件（管脚、器件、约束等配置都在里面）
- 标题栏能立刻告诉你：**开对工程了没有、选对芯片系列了没有**

## 4. 菜单栏（每一个菜单都讲）

菜单从左到右通常是：

`File` → `Edit` → `View` → `Project` → `Assignments` → `Processing` → `Tools` → `Window` → `Help`

### 4.1 File（文件）

最常用：

| 菜单项 | 作用 | 小白何时用 |
|--------|------|------------|
| New / New Project Wizard | 新建文件 / 新建工程向导 | 从零开始做项目 |
| Open / Open Project | 打开文件 / 打开工程 | 打开别人给的工程 |
| Save / Save All | 保存当前 / 全部保存 | 改完代码必点 |
| Close / Close Project | 关闭文件 / 关闭工程 | 换工程前先关 |
| Recent Projects | 最近工程列表 | 快速回到上次项目 |
| Exit | 退出软件 | 下班收工 |

**建议：** 日常打开工程用 `File → Open Project`，不要只打开某个 `.vhd` 文件，否则很多编译/管脚功能不完整。

### 4.2 Edit（编辑）

和普通软件差不多：

- Undo / Redo：撤销 / 重做
- Cut / Copy / Paste：剪切 / 复制 / 粘贴
- Find / Replace：查找 / 替换
- 代码注释、缩进等编辑辅助

### 4.3 View（视图）

用来控制“哪些窗口显示、怎么显示”。

小白最常用：

| 菜单项 | 作用 |
|--------|------|
| Project Navigator | 显示/隐藏左侧工程导航 |
| Tasks | 显示/隐藏左侧任务栏 |
| Messages | 显示/隐藏底部消息窗口 |
| IP Catalog | 显示/隐藏右侧 IP 目录 |
| Utility Windows | 各种辅助窗口入口 |
| Toolbars | 勾选要显示哪些工具栏 |

如果你把某个面板关掉了，别慌：到 `View` 里把它重新勾出来。

### 4.4 Project（工程）

管理“这个工程里有哪些文件、顶层是谁”。

常用：

| 菜单项 | 作用 |
|--------|------|
| Add/Remove Files in Project | 添加/移除源文件 |
| Set as Top-Level Entity | 指定顶层模块（整颗芯片最外层那个） |
| Archive Project | 打包工程（发给别人或备份很好用） |
| Revisions | 工程版本/修订管理 |

**关键概念：Top-Level Entity（顶层实体）**

- FPGA 工程可以有很多模块，但必须有一个“最外层”
- 顶层负责对外接引脚，并把内部子模块连起来
- 你这个工程顶层大概率是 `SSTMC_FPGA`

### 4.5 Assignments（约束与分配）——非常重要

这一栏是“把设计真正接到硬件上”的关键：

| 菜单项 | 作用 | 为什么重要 |
|--------|------|------------|
| Device... | 选择 FPGA 型号 | 选错芯片后面全错 |
| Pin Planner | 图形化管脚分配 | 把信号接到板子对应引脚 |
| Assignment Editor | 表格方式管理约束 | 精细改管脚/电平/时序等 |
| Settings... | 工程综合设置 | 优化策略、文件、仿真等 |
| Timing Analyzer / SDC | 时序约束相关 | 保证时钟频率能跑稳 |

小白先记住两件事：

1. **器件型号**要对（你现在是 `5CEBA2F17C8`）
2. **管脚分配**要对（否则编译过了，板子也不工作）

### 4.6 Processing（处理/编译流程）

这是“开始干活”的菜单：

| 菜单项 | 作用 |
|--------|------|
| Start Compilation | 启动完整编译 |
| Start Analysis & Synthesis | 只做分析与综合 |
| Start Fitter | 只做布局布线 |
| Start Assembler | 只生成编程文件 |
| Start Timing Analysis | 只做时序分析 |
| Stop Processing | 停止当前任务 |

完整编译 = 综合 → 布局布线 → 生成下载文件 → 时序分析（大致流程）。

### 4.7 Tools（工具）

里面有很多独立小工具，新手最常碰：

| 工具 | 作用 |
|------|------|
| Programmer | 下载/烧录到 FPGA |
| IP Catalog | 打开 IP 核目录 |
| Platform Designer（Qsys） | 图形化搭系统（CPU、总线、外设） |
| Signal Tap Logic Analyzer | 在线抓波形（FPGA 版“逻辑分析仪”） |
| In-System Memory Content Editor | 在线看/改存储器内容 |
| Netlist Viewers | 看综合后的电路结构 |
| Tcl Console | 命令行脚本控制 |

小白阶段优先会用：

1. `Programmer`（下载）
2. `IP Catalog`（找现成模块，比如 PLL）
3. 以后再学 Signal Tap（调试神器）

### 4.8 Window（窗口）

管理多窗口布局：平铺、切换、恢复默认布局等。  
窗口弄乱了，可尝试恢复默认或重新勾选 `View` 中的面板。

### 4.9 Help（帮助）

| 菜单项 | 作用 |
|--------|------|
| Getting Started | 入门引导 |
| Help Topics / PDF 手册 | 官方帮助文档 |
| About Quartus Prime | 查看版本信息 |

你截图中间大 Logo 上也能看到版本：`18.1.0 Build 625 Standard Edition`。

## 6. 左上：Project Navigator（工程导航）

这是“工程目录树”，告诉你：

- 工程里有哪些模块
- 模块怎么层层例化（谁调用谁）
- 用了多少逻辑资源
- 目标器件是什么

### 6.1 顶部标签页

常见有：

| 标签 | 含义 |
|------|------|
| **Hierarchy** | 层次结构（最常用） |
| Files | 按文件列表看工程源文件 |
| Design Units | 按设计单元查看 |
| IP Components | 查看工程里用到的 IP |

小白先盯着 **Hierarchy** 看。

### 6.2 Hierarchy 里你看到的内容

典型显示类似：

- 顶层实体名（例如 `SSTMC_FPGA`）
- 下面展开子模块（如 PLL、通信模块、ADC 控制模块等）
- 右侧列：`ALMs needed` / `ALMs used` 等资源统计

#### 什么是 ALM？

- **ALM = Adaptive Logic Module（自适应逻辑模块）**
- 可以粗浅理解成 FPGA 里的“基本逻辑积木块”
- `ALMs needed`：设计大概需要多少
- `ALMs used`：实际用了多少（编译后更准）

资源占用越高，说明设计越大；超过芯片容量就编不过。

### 6.3 器件信息

你会看到类似：

`Cyclone V: 5CEBA2F17C8`

型号拆解（帮助你以后读器件名）：

| 片段 | 含义（简释） |
|------|----------------|
| `5C` | Cyclone V 家族 |
| `E` | 增强型等系列细分（具体以手册为准） |
| `BA2` | 逻辑容量档位 |
| `F17` | 封装/管脚相关信息 |
| `C8` | 速度等级等后缀 |

你现在只需要记住：**这个工程锁定的是这块芯片，不要随便改。**

### 6.4 在 Hierarchy 里能做什么

- 双击模块名：打开对应源文件
- 右键模块：
  - Locate / 定位
  - Set as Top-Level Entity（设为顶层）
  - 查看属性等

## 7. 左下：Tasks（任务流程，最重要）

这是 Quartus 的“流水线看板”。  
FPGA 设计不是按一下就出结果，而是分阶段处理。

### 7.1 Compile Design（编译设计）总流程

展开后通常看到：

1. **Analysis & Synthesis**（分析与综合）
2. **Fitter (Place & Route)**（适配器：布局与布线）
3. **Assembler**（汇编/生成编程文件）
4. **Timing Analysis**（时序分析）
5. **EDA Netlist Writer**（导出给第三方仿真工具的网表，可选）

每一步前面会有状态图标：

| 状态观感 | 通常含义 |
|----------|----------|
| 勾选/绿色完成 | 这一步成功 |
| 旋转/进行中 | 正在跑 |
| 红色叉 | 失败，看 Messages |
| 灰/未开始 | 还没执行 |
| 警告三角 | 过了但有警告 |

### 7.2 每一步到底在干什么（用大白话）

#### （1）Analysis & Synthesis（分析与综合）

- 读你的 VHDL/Verilog
- 检查语法、端口连接是否基本正确
- 把“代码描述”翻译成“逻辑门/触发器网络”

类比：把设计图纸检查一遍，并转成可制造的零件清单。

**失败常见原因：**

- 语法错误
- 端口名写错
- 模块没加入工程
- 位宽不匹配

#### （2）Fitter（Place & Route，布局布线）

- 决定每个逻辑放到芯片哪个物理位置（Place）
- 决定信号怎么走线连接（Route）
- 同时考虑时钟、I/O、资源限制

类比：工厂里把零件安到电路板真实位置，并焊线。

**失败常见原因：**

- 资源不够（逻辑/存储器/PLL 超限）
- 管脚冲突
- 约束不合理导致布不通

#### （3）Assembler（生成下载文件）

成功后会生成可配置 FPGA 的文件，常见：

| 文件 | 用途 |
|------|------|
| `.sof` | SRAM Object File，通过 JTAG 临时下载（掉电丢失） |
| `.pof` | Programmer Object File，常用于烧到配置 Flash（掉电可保存，视板级设计而定） |
| `.jic` 等 | 间接配置文件（进阶，和具体下载方式有关） |

小白先记住：  
**日常调试通常下载 `.sof`。**

#### （4）Timing Analysis（时序分析）

检查：

- 时钟能不能稳定工作在目标频率
- 数据能不能按时到达寄存器
- 有没有建立时间/保持时间违例

就算功能“看起来对”，时序不过也可能在高温、高速时出错。  
新手前期先保证能编译通过，再逐步学时序。

#### （5）EDA Netlist Writer

给 ModelSim 等外部仿真器导出网表。  
不做仿真可以暂时忽略。

### 7.3 Program Device（下载到器件）

Tasks 下方还有 **Program Device**。  
双击它通常会打开 **Programmer** 窗口，用来：

1. 识别下载器（USB-Blaster 等）
2. 选择 `.sof` / `.pof`
3. 勾选 Program/Configure
4. Start 开始下载

## 8. 右侧：IP Catalog（IP 核目录）

**IP = Intellectual Property（知识产权核）**  
意思是：厂商或第三方已经做好的、可直接调用的硬件功能模块。

### 8.1 为什么要用 IP？

有些东西自己从零写又难又容易错，比如：

- PLL（锁相环，做时钟倍频/分频）
- FIFO / RAM
- 乘加器、FFT 等 DSP
- 以太网、PCIe、DDR 控制器
- Nios II 软核 CPU

你的工程里如果有 `sz_pll`，很大概率就是用 IP 生成的 PLL。

### 8.2 目录里常见分类

| 分类 | 里面大概有什么 |
|------|----------------|
| Basic Functions | 基本门、算术、计数器等 |
| DSP | 数字信号处理相关 |
| Interface Protocols | SPI、I2C、UART、Ethernet 等接口 |
| Memory Interfaces / Controllers | 存储器相关 |
| Embedded Processors | 软核处理器 |
| PLL / Clock | 时钟管理 |

### 8.3 右侧上方搜索框

输入关键字（如 `pll`、`fifo`、`ram`）可快速过滤。  
找到后双击，会打开 IP 参数配置向导，生成可加入工程的文件。

### 8.4 小白使用建议

- 先会用现成 IP，不要一上来全手写
- 改 IP 参数后要重新生成，再重新编译
- IP 生成的文件不要随便手动乱改（除非你明确知道在做什么）

## 9. 中间：主工作区

你现在看到的是 Quartus 启动页大 Logo，说明：

- 工程已打开
- 但还没有打开具体源文件/报告窗口

### 9.1 这里会打开什么？

| 内容类型 | 扩展名/形式 | 作用 |
|----------|-------------|------|
| VHDL 代码 | `.vhd` | 硬件描述代码 |
| Verilog 代码 | `.v` | 硬件描述代码 |
| 原理图 | `.bdf` | 图形化连线设计 |
| 报告 | Compilation Report | 资源、时序、错误汇总 |
| Pin Planner | 管脚图 | 分配 I/O |
| 波形/调试窗口 | 视工具而定 | 仿真或在线调试 |

### 9.2 怎么打开代码？

常用方法：

1. 左侧 Hierarchy 双击模块名
2. `File → Open` 打开 `.vhd/.v`
3. `Files` 标签里双击文件

### 9.3 编译报告怎么看？

完整编译后，常会自动或手动打开 **Compilation Report**，重点看：

- Flow Summary：总结果成不成功
- Resource Usage：用了多少逻辑/内存/PLL
- Timing Analyzer：时序过不过
- Fitter → Pin-Out File：最终管脚结果

## 10. 底部：Messages（消息窗口）

这是你的“成绩单 + 报错黑板”。

### 10.1 常见标签页

| 标签 | 看什么 |
|------|--------|
| **System** | 软件系统级消息、工具启动信息 |
| **Processing** | 编译过程详细日志（最常看） |
| **Errors** | 只看错误（优先看这个） |
| **Warnings** | 警告（不一定致命，但要学会判断） |
| **Critical Warnings** | 严重警告（往往需要重视） |
| **Info** | 一般提示信息 |

### 10.2 严重级别怎么理解

| 级别 | 颜色/观感 | 要不要管 |
|------|-----------|----------|
| Error | 红 | 必须修，否则编不过 |
| Critical Warning | 深警告 | 强烈建议处理 |
| Warning | 黄/蓝警告 | 看情况，很多可暂时忽略，但不能全盲视 |
| Info | 普通 | 了解即可 |

### 10.3 小白排错顺序（记住就行）

1. 先点 **Errors** 标签
2. 双击某条错误，常会跳到对应代码行
3. 改完保存，再重新编译
4. 错误清零后，再回头扫一眼 Critical Warnings

### 10.4 你截图里可能看到的提示

例如系统消息提到某些路径下的可执行文件：

- 这通常是软件在定位内部工具或仿真相关程序
- 不一定是你的工程错了
- **真正影响编译成败的是 Errors**

## 12. 小白必会的日常操作流程

下面是一套“从打开工程到板子跑起来”的标准路径。

### 步骤 A：打开工程

1. `File → Open Project...`
2. 选择 `SSTMC_FPGA.qpf`
3. 确认标题栏器件显示为 Cyclone V

### 步骤 B：看懂工程结构

1. 左侧切到 Hierarchy
2. 找到顶层 `SSTMC_FPGA`
3. 双击打开，浏览端口和子模块例化

### 步骤 C：确认器件与管脚（硬件相关时）

1. `Assignments → Device...` 确认 `5CEBA2F17C8`
2. `Assignments → Pin Planner` 检查关键信号是否分配到正确引脚

> 若你只是先学习软件界面、暂不插板子，这一步可先只看不做改动。

### 步骤 D：编译

1. 点工具栏蓝色 ▶，或双击 Tasks 里的 `Compile Design`
2. 盯着底部 Messages
3. 等到全部完成，确认无 Error

### 步骤 E：下载（有板卡和下载器时）

1. 接好供电、USB-Blaster（或板载下载器）
2. `Tools → Programmer`（或 Tasks 里 Program Device）
3. Hardware Setup 选中下载器
4. 添加 `.sof` 文件
5. 勾选 Program/Configure → Start

### 步骤 F：验证

- 看板子指示灯、通信、采样是否正常
- 不正常就回到代码/管脚/时钟配置排查

## 14. 新手常见困惑 FAQ

### Q1：为什么中间是空的，只有个 Logo？

正常。说明工程打开了，但你还没打开具体文件。去左侧 Hierarchy 双击模块即可。

### Q2：Analysis & Synthesis 和 Compile Design 有什么区别？

- `Analysis & Synthesis`：只做前半段检查与综合，快
- `Compile Design`：整条流水线都跑，最终可生成下载文件

想下载到板子，必须完整编译成功（至少到 Assembler）。

### Q3：Warnings 很多是不是一定有大问题？

不一定。FPGA 工程常有大量 Warning。  
优先消灭 Error 和 Critical Warning，再按重要性处理普通 Warning。

### Q4：编译成功但板子没反应，常见原因？

1. 没下载成功（Programmer 没 Start 或硬件没识别）
2. 管脚分配错
3. 时钟没进 FPGA / PLL 没锁
4. 复位逻辑一直处于复位
5. 下载了错的 `.sof`（旧版本）

### Q5：`.sof` 和 `.pof` 怎么选？

- 调试阶段：优先 `.sof`（JTAG 下载，掉电丢失）
- 需要上电自动运行：通常要配置 Flash，并用对应文件流程（`.pof/.jic` 等，取决于板子设计）

### Q6：不小心把窗口关了怎么办？

`View` 菜单里把对应面板重新打开。  
或 `Window` 里恢复布局。

### Q7：IP Catalog 一定要用吗？

不一定。纯手写逻辑也可以。  
但时钟 PLL、存储器、复杂接口，用 IP 更稳更快。

### Q8：Standard Edition 和 Pro Edition 有啥区别？

你现在是 **Standard Edition**。  
不同版本支持的器件家族、部分高级功能有差异。对 Cyclone V 来说，18.1 Standard 是很常见的搭配。
