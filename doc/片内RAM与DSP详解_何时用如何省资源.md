## 1. 先建立总原则

FPGA 里做存储和做乘法，通常有三条路：

| 需求 | 优先方案 | 备选（通常更费） |
|------|----------|------------------|
| 存很多数据 | **片内 RAM（M10K/MLAB）** | 一堆寄存器（触发器） |
| 做乘法/乘加 | **DSP 硬核** | 用 ALM 拼乘法器 |
| 只存几个状态/小变量 | **触发器** | 不必上 RAM |

一句话：

- **大数据 → RAM**  
- **重乘法 → DSP**  
- **少量状态 → 普通寄存器（ALM 里的触发器）**

你这块芯片预算大约是：

- RAM：约 **2 Mb**（M10K 为主）  
- DSP：约 **25 块**（约 50 个 18×18 乘法）

## 2. 片内 RAM：能干什么

### 2.1 它本质上是什么

片内 RAM 是 FPGA 内部的 **专用存储块**（主要是 M10K，也可有 MLAB）：

- 按“地址”读写  
- 适合存大量数据  
- 不像外挂 DDR 那么大，但延迟低、控制简单、不占电路板布线

本工程例子：`RAM_16_2048`

- 位宽 16 bit  
- 深度 2048  
- 容量 = 16 × 2048 = **32768 bit = 32 Kb**  
- 单端口：同一时刻主要按一套地址做读或写（由 `wren` 控制）

### 2.2 常见能做的事（按用途）

#### （1）数据缓存 / 采样缓存

ADC 连续来数据，先写进 RAM，稍后再读出发送或计算。

作用：

- 把“采集速度”和“处理/发送速度”解耦  
- 避免数据来不及处理就丢失

#### （2）FIFO（先进先出队列）

本质也是 RAM + 读写指针。

作用：

- 跨模块缓冲  
- 平滑突发流量  
- 有时用于跨时钟域（需用正规 CDC FIFO IP，不能随手自己拼）

#### （3）查找表 LUT 的“大号版”（ROM/RAM 表）

把复杂公式预计算成表，运行时查表。

例子：

- sin/cos 表  
- 标定曲线  
- 非线性补偿表  

作用：用存储换计算，常能少用 DSP/逻辑。

#### （4）双口缓存（一边写一边读）

如：采集口写，通信口读。

作用：流水作业，提高吞吐。

#### （5）延时线 / 抽头缓存

数字滤波、相关运算里，需要“过去 N 个点”。

作用：给 DSP 算法提供历史样本。

#### （6）系数存储

滤波器系数、控制参数表放 RAM/ROM。

作用：可初始化，有的还能在线更新。

## 3. 片内 RAM：什么时候该用

### 3.1 强烈建议用 RAM 的信号

出现以下特征，优先 RAM：

| 特征 | 例子 | 为什么 |
|------|------|--------|
| 深度大 | ≥ 32、64、128… 甚至上千 | 寄存器堆会爆 |
| 需要按地址随机访问 | `mem(addr)` | RAM 天生如此 |
| 缓存批量数据 | 采样 2048 点 | 典型 RAM 场景 |
| 查找表较大 | 1024 点补偿表 | 用 RAM/ROM 最省 |
| 明确 FIFO 需求 | 收发缓冲 | 用 RAM 实现 |

经验阈值（实用，非绝对）：

- 只要 **深度明显大于“几个/十几个”**，就认真考虑 RAM  
- `array(0 to 2047) of ...` 这种在时钟进程里当寄存器推，通常是灾难写法

### 3.2 和“普通信号寄存器”怎么区分

```vhdl
-- A. 少量状态：用普通信号/寄存器即可（不必 RAM）
signal state : state_t;
signal cnt   : unsigned(7 downto 0);

-- B. 大量按地址存取：应使用 RAM IP / 可综合 RAM 模板
-- 你工程：RAM_16_2048
```

## 4. 片内 RAM：什么时候不该用 / 用不了

### 4.1 不该用 RAM 的情况

| 情况 | 原因 | 该用什么 |
|------|------|----------|
| 只存 1～十几个状态/变量 | RAM 杀鸡用牛刀，还可能浪费整块 M10K | 触发器 |
| 每个时钟要同时读很多无关地址 | 单口/双口端口不够 | 拆多块 RAM，或改架构时间复用 |
| 要“组合逻辑式”即时读、无时钟 | 块 RAM 通常是同步读（要时钟） | 小表可用组合 ROM/常量；或接受 1 拍延迟 |
| 需要任意异步复位清掉每个存储单元内容且当拍全清 | 块 RAM 不擅长像寄存器那样灵活异步清零 | 小存储用寄存器；或接受复位策略限制 |
| 数据量远超约 2 Mb | 片内放不下 | 外挂 SRAM/DDR，或减缓存、压缩、分块 |

### 4.2 “用不了/不好用”的技术限制（很重要）

#### （1）同步 RAM 常有读延迟

很多块 RAM 是：

- 第 N 拍给地址  
- 第 N+1 拍（或再注册后）才稳定读出数据  

所以算法要按“延迟 1 拍/2 拍”设计，不能当普通变量立刻用。

#### （2）同一地址同时读写有规则

`read-during-write` 行为要清楚（读到旧值还是新值），否则仿真和板级不一致。

#### （3）端口数量有限

- 单口：同一时刻基本一套地址  
- 简单双口/真双口：两端可同时访问，但更耗资源、约束更多  

如果你“一边采集写、一边通信读、一边算法再读”，单口一块 RAM 可能不够，需要：

- 换双口  
- 或复制多份（费 RAM）  
- 或分时复用仲裁（费逻辑、降吞吐）

#### （4）位宽/深度映射会浪费

例如你只要 17×1000，也可能被映射成接近标准块大小，实际占用高于理论比特数。

#### （5）不要把片内 RAM 当“硬盘”

掉电丢失；容量小；不适合存巨大日志/文件。

## 5. 片内 RAM：怎么用更省资源

### 5.1 省 RAM 的设计技巧

#### 技巧 1：能共用就别复制

坏例子：

- CH1/CH2/CH3 各开一块完全同构大 RAM，但实际很少同时满负荷  

好方向：

- 能时分复用一块更大/适中 RAM + 通道号寻址  
- 或确认确实需要并行，再复制  

你工程里 `AMC1305_16bit_Controller.vhd` 对 CH1/CH2 各实例化了 `RAM_16_2048`：  
若两通道必须同时独立缓存，这是合理的；若其实可分时，就有优化空间。

#### 技巧 2：深度按 2 的幂、位宽对齐，减少碎片

- 深度 2048、1024、512 通常映射更规整  
- 位宽 8/16/32 更友好  
- 奇怪位宽（如 13bit×1500）可能浪费 M10K

#### 技巧 3：能 ROM 就别做成可写 RAM

只读表（标定、正弦）用 ROM 初始化即可，意图清晰，也便于工具优化。

#### 技巧 4：小而浅优先考虑 MLAB；大而深用 M10K

- 深度很小、位宽很宽：MLAB 可能更合适  
- 深度大：M10K  

通常让 Quartus/IP 自动选；你主要避免“用寄存器硬扛大数组”。

#### 技巧 5：减少同时端口需求

每个额外读口都可能迫使：

- 升到双口  
- 或复制存储  

能“先写后读、分拍访问”就别坚持同拍多口。

#### 技巧 6：缓存只保留必要窗口

不必永远存 2048，若算法只要最近 256 点，就降深度。  
**深度减半，往往近似省一半存储。**

#### 技巧 7：用正规 IP，不要奇异写法

推荐：

- IP Catalog → RAM / FIFO  
- 或遵循厂商可综合 RAM 模板  

不推荐：

- 超大 `signal mem : array(...)` 又期望它进 RAM，却写成异步读写/复杂复位，导致综合成寄存器堆

### 5.2 省逻辑（ALM）的关键：别用寄存器冒充 RAM

```vhdl
-- 危险示意：深度很大时，极易综合成海量触发器
type ram_t is array (0 to 2047) of std_logic_vector(15 downto 0);
signal mem : ram_t;
```

若读写模式不符合块 RAM 推断规则，可能直接把 ALM/寄存器吃爆。  
本工程用 `altsyncram` IP 是正确方向。

### 5.3 读写时序模板（概念）

```vhdl
-- 概念示意：同步单口 RAM 用法
-- 写
if wren = '1' then
  -- 地址 address，数据 data，在 clock 沿写入
end if;

-- 读（常有 1 拍延迟）
-- 本拍给 address，下拍才用 q
```

省资源之外，正确时序能避免你为“修奇怪 bug”再堆额外逻辑。

## 6. DSP：能干什么

### 6.1 它本质上是什么

DSP 块是芯片里的 **乘法/乘加专用硬件**：

- 专门做 `A*B`、`A*B+C` 这类运算  
- 比用 ALM 拼乘法更快、更省逻辑、时序更好  

你芯片大约：

- 25 个可变精度 DSP 块  
- 约等于 50 个 18×18 乘法器

### 6.2 DSP 常见能做的事

| 运算 | 含义 | 典型应用 |
|------|------|----------|
| 乘法 | `y = a * b` | 增益、标定、混频 |
| 乘加 MAC | `y = a*b + c` | FIR 滤波核心 |
| 预加再乘 | `y = (a±b)*c` | 对称滤波 |
| 累加链 | 连续累加乘积 | 滤波器、相关 |
| 多通道乘加 | 多路并行 | 多相滤波、并行列运算 |

一句话：  
**凡是“数字很多、反复乘”的地方，DSP 就是主力。**

## 7. DSP：什么时候该用

### 7.1 强烈建议走 DSP 的场景

| 场景 | 例子 | 原因 |
|------|------|------|
| 明确滤波 | FIR/IIR | MAC 密集 |
| 标定换算 | `y = (x * k + b) / 2^n` | 有乘法 |
| 功率/能量 | `i*v`, `x*x` | 乘法 |
| 控制算法中的乘系数 | PI/PID 中的 Kp*e | 乘法 |
| 相关/卷积 | 滑动匹配 | 大量 MAC |
| 矩阵小块运算 | 点积 | 乘法累加 |

### 7.2 代码里哪些写法容易映射到 DSP

```vhdl
y <= a * b;
acc <= acc + (a * b);
y <= resize(a * b, y'length);
```

以及本工程风格（整数换算）这类：

```vhdl
-- 概念上含乘法/常数乘
sig_T1s <= ... (sig_T1O * 225 - 18118) / 16384 ...
Driveou1 <= (var_Drive * 307) / 4096;
CH1_yk := CH1_yk1d + CONV_INTEGER(sig_P17t) * CH1_ek;
```

这些乘号 `*`，综合器常会尝试用 DSP 实现（也取决于位宽、是否常量、是否在时序区域、综合设置）。

### 7.3 “常量乘法”也可能用 DSP 或移位加法

例如 `x * 225`：

- 可用 DSP  
- 也可能拆成移位+加法（用 ALM）  

何者更优看位宽、时序、综合策略。对新手：先保证功能与时序，再在报告里看它到底映射到了哪。

## 8. DSP：什么时候不该用 / 用不了

### 8.1 不该强行用 DSP 的情况

| 情况 | 原因 | 更好做法 |
|------|------|----------|
| 只有 1 位/极小位宽简单逻辑 | DSP 浪费 | LUT 即可 |
| 主要是加减、移位、选择 | DSP 帮不上大忙 | ALM |
| 可用 `x<<n` 或很少几次加代替的极简单常量乘 | 可能更省 | 移位加法 |
| DSP 已经用满，还继续并行堆乘法 | 编不过/变逻辑乘法爆 ALM | 时间复用、降并行、降位宽 |
| 需要非常奇怪的位宽/非同步风格，导致无法推断 | 工具可能不用 DSP | 改写成标准乘法寄存器管道，或调用 IP |

### 8.2 DSP 的现实限制

#### （1）数量有限

大约 25 块，不是无限算力。  
多通道全并行 FIR 很容易见底。

#### （2）位宽有“甜蜜区”

常见高效区在 9×9、18×18、接近 27×27 等模式。  
位宽过大要级联多个 DSP，占用上升。

#### （3）不是所有 `*` 都会进 DSP

可能条件：

- 乘在复杂条件深处，推断失败  
- 用了不适合的类型/函数写法  
- 综合选项关闭了相关推断  
- 被你手动压成常量移位结构  

#### （4）DSP 解决不了“存储不足”

DSP 负责算，不负责存大数据。  
滤波历史样本仍要 RAM/寄存器。

#### （5）除法 `/` 通常不是 DSP 强项

硬件除法很贵。  
工程里常见 ` / 16384`、`/ 4096` 其实是 **2 的幂除法 = 右移**，这很好。  
但 `/ 20000` 这种非 2 的幂，可能很吃资源或要多拍算法除法，优先考虑：

- 改成近似移位  
- 或乘倒数（DSP 乘）+ 移位  
- 或降低更新频率、多拍完成

## 9. DSP：怎么用更省资源

### 9.1 省 DSP 的核心策略

#### 策略 1：时间复用（最重要）

不要 8 通道同时各用一套乘法器，可以：

- 1 套乘法器  
- 8 拍轮流算 8 通道  

代价：吞吐变慢；收益：DSP 少很多。

#### 策略 2：能移位就别真乘

```text
x * 2   = 左移 1
x * 4   = 左移 2
x / 4096 = 右移 12
x / 16384 = 右移 14
```

你工程里大量 `/16384`、`/4096` 就是好的省资源写法方向。

#### 策略 3：降低位宽

乘法资源近似随位宽变贵。  
输入先裁剪/饱和到够用的位宽，再乘。

#### 策略 4：降并行，提流水

- 全组合大表达式：又吃资源又难时序  
- 拆成多拍 MAC：更易映射 DSP，也更好跑时钟

```vhdl
-- 概念：一拍做一次乘加，多拍完成滤波
acc <= acc + (sample * coeff);
```

#### 策略 5：对称滤波省乘

FIR 对称系数可让 ` (x0+xN)*b0 `，减少乘法次数（预加再用 DSP）。

#### 策略 6：用官方 IP（进阶）

- LPM_MULT / ALTERA_MULT_ADD  
- FIR Compiler 等  

需要强约束或确定映射时更稳。

#### 策略 7：先看报告再优化

Compilation Report 里看：

- DSP block usage  
- 是否大量 Unexpected 逻辑乘法（ALM 暴涨）  

再决定是“加流水”还是“改时间复用”。

### 9.2 推荐的乘法写法习惯

更利于推断/维护：

1. 用 `ieee.numeric_std` 的 `unsigned/signed`  
2. 乘法结果注意位宽（a 宽 + b 宽）  
3. 在时钟进程里分拍完成  
4. 2 的幂缩放优先移位  
5. 避免在超复杂组合网络里塞很多 `*`

## 10. RAM vs DSP vs 逻辑：选型决策树

### 10.1 我要“存数据”

```text
数据量很小（几个到十几个）？
  ├─ 是 → 用普通寄存器
  └─ 否 → 要按地址访问/缓存/FIFO/查表？
            ├─ 是 → 用片内 RAM
            └─ 否 → 重新定义需求
```

### 10.2 我要“做运算”

```text
主要是与或选择比较？
  ├─ 是 → LUT/ALM
  └─ 否 → 有乘法/乘加？
            ├─ 是 → 优先 DSP
            │         └─ DSP不够 → 时间复用 / 降位宽 / 降通道并行
            └─ 否 → 加减计数 → ALM 进位链
```

### 10.3 我要“又存又算”（滤波典型）

```text
样本历史 → RAM（或短的用寄存器）
系数     → ROM/RAM 或常量
乘加循环 → DSP
控制状态 → ALM 触发器 + LUT
```

## 11. 对照本工程 SSTMC_FPGA

### 11.1 片内 RAM：已经在用

`RAM_16_2048` + `AMC1305_16bit_Controller.vhd`：

- 作用：把 16 位采样/中间量按地址缓存  
- 这是标准且正确的“采集侧缓存”用法  
- 若 CH1/CH2 同时需要独立历史，双实例合理  
- 省资源检查点：深度 2048 是否必要、两通道是否必须各一份

### 11.2 DSP：算法里大量乘法，潜在用户

顶层中可见大量：

- `* 225`、`* 307`、`* sig_P17t`、`* sig_P16t`  
- 后接 `/16384`、`/4096`、`/20000` 等缩放  

含义：

- 乘法部分：应尽量让工具映射 **DSP**  
- `/16384`、`/4096`：本质右移，省资源友好  
- `/20000`：非 2 的幂，可能更贵，是后续优化观察点  

### 11.3 对你这种项目的实践建议

1. 采样缓存继续用 RAM IP（已做对）  
2. 控制状态机继续用寄存器，不要塞 RAM  
3. 标定/控制里的乘法，接受走 DSP  
4. 编译后重点看：  
   - Memory bits / M10K  
   - DSP blocks  
   - ALM 是否因乘法推断失败而暴涨  
5. 若 DSP 紧张：先做通道时间复用，再动算法并行度

## 12. 实操清单（建议收藏）

### 片内 RAM

**该用时**

- 深度大、要地址访问、FIFO、查表、采样缓存

**别用时**

- 只存很少变量  
- 要求无时钟组合直读且表还很大（需改架构）  
- 同拍太多独立读口却只有单口 RAM

**省资源**

- 降深度、对齐位宽、少复制、能 ROM 用 ROM、正规 IP、避免寄存器大数组

### DSP

**该用时**

- 乘法、乘加、滤波、标定增益、点积相关

**别用时**

- 纯逻辑控制  
- 可用移位替代的简单 2^n 缩放（优先移位）  
- DSP 已满还盲目全并行

**省资源**

- 时间复用、降位宽、降并行、对称滤波、2^n 用移位、多拍 MAC、看报告再改

## 附录 A：最小对照例

### RAM 用法（概念）

```vhdl
-- 写采样
if sample_valid = '1' then
  wr_addr <= wr_addr + 1;
  -- 把 sample 写入 RAM[wr_addr]
end if;

-- 稍后按地址读出发送/计算
rd_data <= ram_q;  -- 注意同步读延迟
```

### DSP 用法（概念）

```vhdl
process(clk)
begin
  if rising_edge(clk) then
    -- 一拍乘加（易映射 DSP）
    acc <= acc + (signed(sample) * signed(coeff));
  end if;
end process;
```

### 不该这样省事（示意）

```vhdl
-- 1) 超大数组当寄存器乱读写
-- 2) 同拍无仲裁地“三处同时读同一单口RAM”
-- 3) 几十通道全并行大位宽乘法还不做流水/复用
-- 4) 频繁非2^n除法还不改算法
```

## 附录 B：一句话最终记忆

| 资源 | 一句话 |
|------|--------|
| **RAM** | 用来“放很多数”，按地址存取；大数据缓存/FIFO/查表就靠它 |
| **DSP** | 用来“狠狠地乘”，滤波标定乘加就靠它 |
| **省资源** | RAM 靠减深度/少复制/对齐；DSP 靠时间复用/降位宽/能移位就移位 |
| **不能幻想** | RAM 不是无限硬盘；DSP 不是无限计算器；端口、延迟、数量都是硬约束 |
